# Research Audit

| Source | Year | Contribution | SkillLLM_v2 application | Implementation effect |
|---|---:|---|---|---|
| [Skill-LLM: Repurposing General-Purpose LLMs for Skill Extraction](https://arxiv.org/abs/2410.12052) | 2024 | Shows that supervised LLM adaptation can improve skill extraction quality. | Supports using a fine-tuned Mistral LoRA as the main extraction anchor. | Current: keep the LLM extractor as the anchor and evaluate wrappers separately. |
| [SkillSpan: Hard and Soft Skill Extraction from English Job Postings](https://aclanthology.org/2022.naacl-main.366/) | 2022 | Introduces expert span annotations for hard and soft skills in job postings. | Defines the benchmark, labels, and exact boundary pressure used here. | Current: use test split for extraction metrics; preserve hard/soft labels. |
| [GLiNER: Generalist Model for Named Entity Recognition using Bidirectional Transformer](https://aclanthology.org/2024.naacl-long.300/) | 2024 | Generalist NER with arbitrary labels using a compact bidirectional encoder. | Useful as a recall booster and baseline, not a replacement for the tuned LLM. | Current: add-only auxiliary candidates behind non-regression gates. |
| [QLoRA: Efficient Finetuning of Quantized LLMs](https://arxiv.org/abs/2305.14314) | 2023 | Memory-efficient LoRA fine-tuning through frozen 4-bit quantized backbones. | Justifies local Mistral adapter training on constrained GPUs. | Current: reuse trained adapter; do not retrain during refresh. |
| [From Local to Global: A Graph RAG Approach to Query-Focused Summarization](https://arxiv.org/abs/2404.16130) | 2024 | Uses graph-based structure for corpus-level reasoning beyond naive chunk retrieval. | Supports downstream graph reasoning after extraction and normalization. | Current: keep graph reasoning out of the extraction gate. |
| [Contextual Retrieval in AI Systems](https://www.anthropic.com/engineering/contextual-retrieval) | 2024 | Adds document context to chunks to improve retrieval reliability. | Supports contextualized job/course retrieval with evidence. | Current: add deterministic contextual retrieval helper; dense/reranker later. |
| [Don't Do RAG: When Cache-Augmented Generation is All You Need for Knowledge Tasks](https://dl.acm.org/doi/10.1145/3701716.3715490) | 2025 | Frames cache-augmented generation as useful when stable knowledge fits in context. | Use CAG for stable profile/taxonomy/course summaries, not for changing job feeds. | Current: add cached context packet; keep job postings in RAG. |
| [Versioning Data and Models](https://doc.dvc.org/example-scenarios/versioning-data-and-models) | 2026 | Documents Git-compatible practices for data/model artifact versioning. | Motivates artifact manifests, stale checks, and metrics provenance. | Current: refresh manifest, provenance report, and artifact path tables. |

## Summary

The literature supports a two-part design: a supervised/fine-tuned extractor for boundary-sensitive SkillSpan extraction, then a guarded wrapper for normalization, context, and graph reasoning. GLiNER is useful as a lightweight recall source, but the local metrics show it must be add-only and gated. GraphRAG, Contextual Retrieval, and CAG support downstream job/course reasoning but do not justify changing extraction spans after the Raw Mistral anchor has already produced stronger SkillSpan metrics.
